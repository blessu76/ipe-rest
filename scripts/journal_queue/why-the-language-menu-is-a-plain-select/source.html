Why the language menu is a plain select

언어 메뉴가 평범한 select 인 까닭

The language menu in the header is the ordinary select element that every browser already knows how to draw, and that was a deliberate choice.

Twelve languages, twelve addresses

This site is written in twelve languages: English, Korean, Japanese, Traditional Chinese, Spanish, Brazilian Portuguese, French, German, Indonesian, Thai, Vietnamese and Turkish. None of them is a layer on top of another. Each language has its own pages at its own address, so a page in Japanese is a real page that can be linked to, bookmarked and found by a search engine. The menu is only a way to move between those addresses, and each option points at the same page in another language.

Why not something fancier

A menu with flags, animated panels and a search field can look impressive, but it has to be built from scripts and styles that are loaded every time, and every custom piece is a place where something can break for somebody. A native select has no such problem. On a phone it opens the system picker, which is large, familiar and easy to use with a thumb. With a keyboard it opens and closes the way people expect. A screen reader announces it as a list of choices with the current one selected. Nobody had to design any of that, and nobody has to maintain it.

Names, not flags

The options are the names of the languages, each written in that language, so a person who reads only Thai can find Thai without understanding the word for language in any other. We left the flags out because a language is not a country, and many people read more than one language.

What it remembers

When you choose a language, the page saves your choice in your browser under one name, ipe_lang, and opens the matching page. The next time you arrive at the front door, the site looks at that saved choice first, then at the language your browser reports, and falls back to English if it has nothing else to go on. Your choice always wins over a guess. The choice never leaves your device.

Without scripts

If scripts are turned off, a select that changes the page by itself cannot work. For that case the menu is replaced by a short list of plain links, one for each language. They are ordinary anchors, so they work in any browser, in a reader mode, and for any crawler that wants to see which languages exist. The page stays useful with nothing at all running.

A small control that always works is worth more than a clever one that usually does. This one is small on purpose.

헤더의 언어 메뉴는 모든 브라우저가 이미 그릴 줄 아는 평범한 select 요소이고, 이것은 의도한 선택입니다.

열두 언어, 열두 주소

이 사이트는 열두 언어로 쓰여 있습니다. 영어, 한국어, 일본어, 중국어 번체, 스페인어, 브라질 포르투갈어, 프랑스어, 독일어, 인도네시아어, 태국어, 베트남어, 터키어입니다. 어느 것도 다른 언어 위에 덧씌운 층이 아닙니다. 언어마다 자기 주소에 자기 페이지가 있어서, 일본어 페이지는 링크하고 북마크하고 검색 엔진이 찾을 수 있는 진짜 페이지입니다. 메뉴는 그 주소들 사이를 오가는 길일 뿐이고, 옵션은 각각 같은 페이지의 다른 언어판을 가리킵니다.

더 화려한 것을 쓰지 않은 이유

깃발, 움직이는 패널, 검색 칸이 있는 메뉴는 근사해 보이지만, 매번 불러와야 하는 스크립트와 스타일로 만들어야 하고, 맞춤 부품 하나하나가 누군가에게는 고장 날 수 있는 자리입니다. 기본 제공 select 에는 그런 문제가 없습니다. 폰에서는 시스템 선택창이 열리는데, 크고 익숙하고 엄지로 쓰기 쉽습니다. 키보드에서는 사람들이 기대하는 대로 열리고 닫힙니다. 화면 낭독기는 현재 선택이 표시된 선택지 목록으로 읽어 줍니다. 그중 어느 것도 누가 설계할 필요가 없었고, 누가 관리할 필요도 없습니다.

깃발이 아니라 이름

옵션은 언어의 이름이고, 각각 그 언어로 적혀 있습니다. 그래서 태국어만 읽는 사람도 다른 언어로 쓰인 언어라는 낱말을 몰라도 태국어를 찾을 수 있습니다. 깃발을 뺀 것은 언어가 나라가 아니고, 많은 사람이 둘 이상의 언어를 읽기 때문입니다.

기억하는 것

언어를 고르면 페이지는 선택을 브라우저에 ipe_lang 라는 이름 하나로 저장하고 해당 페이지를 엽니다. 다음에 대문으로 들어오면 사이트는 저장된 선택을 먼저 보고, 그다음 브라우저가 알려 주는 언어를 보고, 더 단서가 없으면 영어로 갑니다. 추측보다 당신의 선택이 언제나 앞섭니다. 선택은 당신의 기기를 떠나지 않습니다.

스크립트가 없을 때

스크립트가 꺼져 있으면 스스로 페이지를 바꾸는 select 는 동작할 수 없습니다. 그 경우를 위해 메뉴는 언어마다 하나씩 있는 짧은 일반 링크 목록으로 바뀝니다. 평범한 앵커라서 어떤 브라우저에서도, 읽기 모드에서도, 어떤 언어가 있는지 보려는 크롤러에게도 동작합니다. 아무것도 실행되지 않아도 페이지는 쓸모가 있습니다.

How little a journal page has to load

저널 한 페이지가 불러오는 것은 얼마나 적은가

A page that opens quickly is easier to read, especially on a phone with a weak signal. Here is what one journal page on ipe.rest actually loads, with the sizes we measured, and what it leaves out on purpose.

Yesterday’s entry was about small choices that help readers. This one is about the weight behind them. We took the entry from 5 November, the English page, and looked at the files it asks for. The numbers are from 6 November 2026.

One small page

The page itself is a single HTML file of 30,871 bytes. Sent over the wire it is compressed to 8,255 bytes, which is about 8 KB. The styles are written inside that file rather than in a separate stylesheet, so there is no second request to wait for before the text can be laid out. The body of the page has no images at all; only the small link preview image, which is never shown on the page, is named in its head.

One script, and what it does

The page loads one script of 6,218 bytes, about 2.3 KB compressed. It does the small jobs a static page still needs: it switches between languages, remembers your choice in your browser, and counts visits. There is no framework behind it and nothing to install.

Fonts from our own server

The text is set in Inter, with JetBrains Mono for the small labels. Both are open fonts, and the files are served from ipe.rest itself: 27,540 bytes for Inter and 20,420 and 21,164 for the two weights of the mono face. No font is fetched from another company’s server, so no font request ever leaves for anyone else.

The fonts are set to swap. Your browser shows the words straight away in a font it already has, and replaces it when the font file arrives. Reading never waits on a download.

Added up

Add the compressed page, the compressed script and all three font files, and a first visit comes to roughly 80 KB. Later visits are lighter, because your browser and the site’s own cache keep the files and the pages still open offline, as we described earlier this week.

What comes from elsewhere

One thing does not come from our server: the analytics script from Google, which loads after the page and which the privacy page describes. It is not counted in the 80 KB above, and the text reads the same without it.

What we have not measured

We measured file sizes, not how long a page takes to appear on a slow connection or an old phone. Sizes also drift as entries get longer and as we change the styles, so treat these as a snapshot of one page on one day.

None of this is a record to beat. It is a habit: before adding something to a page, ask whether the reader will miss it if it is gone.

빨리 열리는 페이지는 읽기도 쉽습니다. 신호가 약한 휴대폰에서는 더 그렇습니다. ipe.rest 저널 한 페이지가 실제로 무엇을 불러오는지, 우리가 잰 크기와 함께 적고, 일부러 뺀 것도 함께 적었습니다.

어제 글은 독자를 돕는 작은 선택들에 관한 것이었습니다. 이번 글은 그 뒤에 있는 무게에 관한 것입니다. 11월 5일 글의 영어 페이지를 골라 그 페이지가 요청하는 파일을 살펴보았습니다. 숫자는 2026년 11월 6일에 잰 것입니다.

작은 페이지 하나

페이지 자체는 30,871바이트짜리 HTML 파일 하나입니다. 전송될 때는 8,255바이트, 곧 약 8KB 로 압축됩니다. 스타일은 별도의 스타일시트가 아니라 그 파일 안에 들어 있어서, 글자를 배치하기 전에 기다려야 하는 두 번째 요청이 없습니다. 페이지 본문에는 이미지가 전혀 없습니다. 페이지에 보이지 않는 작은 링크 미리보기 이미지만 머리 부분에 이름이 적혀 있습니다.

스크립트 하나, 그리고 하는 일

페이지는 6,218바이트, 압축하면 약 2.3KB 인 스크립트 하나를 불러옵니다. 정적인 페이지에도 필요한 작은 일을 합니다. 언어를 바꾸고, 여러분의 선택을 브라우저에 기억하고, 방문 수를 셉니다. 그 뒤에 프레임워크는 없고 설치할 것도 없습니다.

우리 서버에서 오는 글꼴

글자는 Inter 로 쓰고, 작은 라벨에는 JetBrains Mono 를 씁니다. 둘 다 열린 글꼴이고, 파일은 ipe.rest 에서 직접 내려보냅니다. Inter 는 27,540바이트, 고정폭 글꼴의 두 굵기는 20,420바이트와 21,164바이트입니다. 다른 회사의 서버에서 글꼴을 가져오지 않으므로, 글꼴 요청이 다른 곳으로 나가는 일은 없습니다.

글꼴은 바꿔치기(swap) 방식으로 설정되어 있습니다. 브라우저는 이미 가진 글꼴로 글자를 곧바로 보여 주고, 글꼴 파일이 도착하면 바꿉니다. 읽는 일은 내려받기를 기다리지 않습니다.

모두 더하면

압축된 페이지, 압축된 스크립트, 글꼴 파일 세 개를 모두 더하면 처음 방문은 대략 80KB 입니다. 이후 방문은 더 가볍습니다. 브라우저와 사이트 자체의 캐시가 파일을 간직하고, 이번 주 앞서 설명했듯 페이지가 오프라인에서도 열리기 때문입니다.

바깥에서 오는 것

하나는 우리 서버에서 오지 않습니다. 페이지가 열린 뒤에 불러오는 구글의 분석 스크립트이고, 개인정보처리방침 페이지에 설명되어 있습니다. 위의 80KB 에는 들어 있지 않고, 이것이 없어도 글은 똑같이 읽힙니다.

아직 재지 않은 것

우리는 파일 크기를 쟀을 뿐, 느린 회선이나 오래된 휴대폰에서 페이지가 나타나는 데 걸리는 시간은 재지 않았습니다. 글이 길어지고 스타일을 바꾸면 크기도 달라지므로, 이 숫자는 어느 하루의 한 페이지를 찍은 기록으로 보아 주세요.

ipe(); // a page is just a file
